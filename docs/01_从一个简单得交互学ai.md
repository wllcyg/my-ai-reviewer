## 从简单概念开始：什么是 Agent？
![image](https://api.cheatppf.xyz/i/2go5er8m6iw-ijuxgd.png)
大家都在谈论 Agent，但 Agent 究竟是什么？从今天开始，我们从零开始进入 Agent 内容的开发学习。

其实理解 Agent 并不复杂，可以用一个简单的公式概括：

> **Agent = LLM（大脑）+ Tool（手脚）+ Prompt（指令与输入）**


### 1. LLM（大脑）：负责思考与决策的核心

首先聊聊 **LLM（大语言模型）**，它是整个 Agent 的**大脑和决策中枢**。

作为初学者，在现阶段**完全不需要**一上来就钻研 Transformer 架构或复杂的预训练算法。在应用层，我们只需要把它当作一个可以通过 API 调用的“超级思考引擎”。

这个“大脑”主要帮我们解决三件事：
1. **理解真实意图**：听懂用户的核心需求（很多时候用户表达出来的字面意思，并不是他真正想要的）。
2. **任务拆解与规划**：把模糊、复杂的任务，拆解成一步步可落地的执行步骤。
3. **行动决策与推演**：在真正干活之前先思考推演一遍，判断“下一步该干什么”、“要不要调工具”、“传什么参数”。


### 2. Tool（手脚与感官）：把想法变成行动

如果说 LLM 只是一个“脑子灵光、很会聊天”的专家，那么没有 **Tool（工具）** 的它，充其量只能“纸上谈兵”。

比如你问它：“今天深圳天气怎么样？帮我把桌面上的文件压缩后发邮件给小张。”
- **只有脑子**：它只能回答：“我不知道实时天气，我也没有权限操作你的电脑文件。”
- **装上手脚（Tool）**：它会先调用天气接口查温度，再调用系统脚本压缩文件，最后调用邮件接口把信发出去。

#### 本质上，Tool 到底是什么？
作为开发者，不要把 Tool 想得太神秘。**Tool 在代码层面上，本质就是一个个普通的函数（Function / API）**。
比如：
- `searchGoogle(keyword)`：赋予它**眼睛**，让它能看实时网络、读文件、查数据库；
- `executeCommand(cmd)`、`sendEmail(to, content)`：赋予它**双手**，让它能写代码、跑程序、调外部接口改变现实。


### 3. Prompt（指令与上下文）：怎么指挥大脑与手脚？

很多人以为“提示词”就是你在聊天框里发的那句话。但如果只把用户的话发给大模型，它是玩不转 Agent 的。

在代码里，每次我们跟大模型对话，背后其实一次性打包塞了 **5 样东西**：

1. **System Prompt（系统提示词）**：
   - 开发者写死的，用户一般看不到。
   - 比如："你是个程序员，写代码必须保存成文件，遇到不懂的先查工具，不准瞎猜。"
2. **Tool Definitions（工具说明书）**：
   - 告诉它手里有哪些工具、每个参数怎么传。
   - 不给这份说明书，大模型不知道自己能调哪些工具。
3. **User Message（用户消息）**：
   - 用户在输入框里敲的话，比如"帮我写个贪吃蛇"。
4. **Assistant Message（AI 的回应）**：
   - 大模型自己输出的内容。可能是在思考，可能是要调工具（比如"我要调 `write_file`"），也可能是最后汇报结果。
5. **Tool Result（工具的反馈）**：
   - 工具跑完后回传的结果（比如"文件已写入成功"）。模型看了结果，才知道事办成没有、下一步该干嘛。

---

#### 串起来看：它们在代码里是怎么聊天的？

别看上面有 5 个名词，在我们的代码里（比如 `01_base_agent/agent.py`），其实就是一个大家排排坐的列表数组（`messages`）：

```text
1. System:    "你是个专业助手，写代码必须保存成文件..."
2. Tools:     [list_files, read_file, write_file]
3. User:      "帮我写个贪吃蛇"
4. Assistant: "好，我决定调用 write_file('snake.html', '...')"
5. Tool:      "成功写入 1520 字符"
6. Assistant: "搞定！文件已写好，直接双击 html 就能玩。"
```

## 4. 扒开外衣：我们写的这个 Agent 到底是个啥？

Agent 的本质，就是一个平平无奇的 `while` 循环。点开仓库代码一看，逻辑超级简单：

> **一个 `while` 循环，来回问、找、干、完。**

1. **问**：把聊天记录发给大模型，问它下一步做什么；
2. **找**：大模型返回要调用的函数名和参数，比如“跑个命令”或者“写个文件”；
3. **干**：Python 代码去执行命令、写文件，再把结果追加到聊天记录里；
4. **完**：大模型看到结果，发现任务已经完成，直接输出一段汇报，循环 `break` 结束。

Agent 核心就这么点东西，比学 Vue 和 React 状态管理容易多了，这是我觉得哈。

### 但真正动手写，其实还有一些坑

现在大部分代码都是 AI 写的，我只是做了微调。

很多人以为写个循环就叫 Agent 了，真到实战里，哪怕命令少打一个参数，程序都能原地卡死。另外无论什么时候，都要限制 AI 的循环次数，防止 token 刷爆。

#### 坑 1：命令行中有选择，直接卡死
- AI 跑 `pnpm create vite`，结果控制台弹出了 `Which linter to use? Oxlint 还是 ESLint？`，需要按方向键。程序直接卡死在那儿傻等键盘输入。
- 理想做法是让 AI 只生成命令，由人手动执行。如果必须自动执行，就在底层把键盘输入掐死（`DEVNULL`），再塞个环境变量 `CI=true`，用默认配置秒级生成。

#### 坑 2：启动网页服务，整个程序又卡死了
- AI 代码都写好了，它最后执行 `pnpm dev` 想把项目跑起来，结果程序又死死定住两分钟，直到超时被强制杀掉。
- 解决办法：`pnpm dev` 是个网页服务器，它会一直在后台监听端口，根本不会自动退出！咱们给它加了个“后台守护模式”，只要瞄一眼终端，抓到了 `http://localhost:5173` 这个网址，让服务在后台接着跑，主程序继续往下走。

#### 坑 3：`cd` 到处乱蹦
- AI 像人类一样，动不动就想 `cd snake-game`。但 Python 跑命令每次都是独立的临时窗口，`cd` 完了窗口就关了，根本记不住位置，甚至还可能 `cd ..` 跑去删你的系统文件。
- 解决办法：直接写了个正则表达式硬拦，让它用提供的安全目录参数。

#### 坑 4：一等半分钟，你以为电脑死机了
- 让 AI 写几百行贪吃蛇代码，屏幕上十几秒一个字没有，谁看谁觉得死机了。
- 解决办法：加上 `stream=True` 流式输出，让大模型一个字一个字往外蹦，像打字机一样。
