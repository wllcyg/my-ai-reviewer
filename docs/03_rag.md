## RAG 学习

今天开始学习 RAG（检索增强生成）相关知识。

---

### 什么是 RAG

**RAG** 的全称是 **Retrieval-Augmented Generation（检索增强生成）**。

简单来说，就是**在让大模型回答问题之前，先去外部知识库里“翻翻书”（检索），把相关内容和用户问题一起喂给模型（增强），最后让模型生成回答（生成）**。

通俗比喻：
- **普通大模型提问**：闭卷考试，全靠模型脑子里的预训练记忆（容易遗忘、编造或时效滞后）。
- **RAG 模式提问**：开卷考试，先翻教材找到对应参考段落，再结合段落来答题。

---

### 为什么需要 RAG

大模型虽然强大，但在实际业务落地时有几个硬伤：

1. **知识幻觉**：遇到不知道的内容容易一本正经地胡说八道。
2. **私有领域数据缺失**：企业内部文档、代码库、业务规范，公网大模型根本没学过。
3. **时效性滞后**：模型训练有截止日期，无法实时获取最新资讯。
4. **微调成本高昂**：重新训练或微调模型成本高、周期长，且难以实时增删数据。

---

### RAG 的核心三步走

```text
[ 准备阶段: 文档入库 ]
原始文档 -> 切块 (Chunking) -> 向量化 (Embedding) -> 存入向量数据库 (Vector DB)

[ 提问阶段: 检索与生成 ]
用户提问 -> 提问向量化 -> 检索匹配相关片段 (Retrieval) -> 拼接 Prompt (Augmented) -> 大模型回答 (Generation)
```

1. **检索（Retrieval）**：根据用户的问题，在知识库/向量库中找出最相关的文档片段。
2. **增强（Augmentation）**：把找到的相关知识片段拼接到 Prompt 里，作为背景参考资料。
3. **生成（Generation）**：模型参考这些真实资料，输出精准、带出处的回答。

---

### 核心概念速览

| 概念 | 含义与通俗解释 |
|---|---|
| **Chunk（切片/分块）** | 将长文本切成 200~1000 字的小段落，便于精准匹配 |
| **Embedding（词向量/向量化）** | 把文本转成多维数字数组，让机器能够计算语义相似度 |
| **Vector DB（向量数据库）** | 专门用来高效存储和做“相似度搜索”的数据库（如 Chroma、Pinecone、Milvus） |
| **Top-K** | 检索时按相似度由高到低，取排名前 K 个最相关的片段 |

---

### 向量相似度的三种对比算法（距离度量方式）

在向量检索时，向量数据库用来衡量“用户问题与文档片段相似度”主要有以下三种计算方式：

| 度量方式 | 关注重点 | 通俗比喻 | 数值判定 | 适用场景 |
|---|---|---|---|---|
| **余弦相似度 (Cosine Similarity)** | 只看**夹角（方向）**，忽略向量长度 | 两个人**三观是否一致**（说话长短不影响三观） | 范围 `[-1, 1]`，**越大越相似** | **文本 RAG 最常用**，长短句混合检索不受长度干扰 |
| **点积 / 内积 (Dot Product / IP)** | 既看**方向**，又看**向量模长（强度）** | 两个人不仅三观要合，而且“能量要强” | 范围 `(-∞, +∞)`，**越大越相似** | 检索速度极快。**向量归一化后，点积在数学上等价于余弦相似度** |
| **欧氏距离 (Euclidean / L2)** | 两个向量端点之间的**直线物理距离** | 空间中两栋楼的直线物理距离 | 范围 `[0, +∞)`，**越小越相似**（0为完全重合） | 图像比对、推荐系统聚类；文本 RAG 较少单用 |

> **工业落地秘诀**：生产环境中推荐将向量做**归一化（Normalize，将模长变为 1）+ 点积检索**，既能获得余弦相似度对语义方向的精确把握，又能享受点积在硬件矩阵计算上的极致速度。

---

### RAG vs 微调 (Fine-tuning)

| 维度 | RAG（检索增强） | Fine-tuning（微调） |
|---|---|---|
| **适用场景** | 补充动态知识、企业文档、问答查证 | 改变语言风格、特定格式输出、专业任务技巧 |
| **数据更新** | 极快（直接往数据库增删文件） | 慢（需要重新准备数据集并训练） |
| **幻觉控制** | 好（有据可查，可附带引用来源） | 一般（依然存在记忆偏差与幻觉） |
| **实施成本** | 低到中等，工程开发为主 | 高，需要算力与专业算法调优 |

### 最简单的 RAG 伪代码逻辑

```python
# 1. 检索阶段
query = "项目部署流程是什么？"
relevant_docs = vector_db.search(query, top_k=3)

# 2. 增强阶段（组装上下文）
context = "\n".join(relevant_docs)
prompt = f"""请严格依据以下参考资料回答用户的问题。如果资料未提及，请明确说明不知道。

【参考资料】：
{context}

【用户问题】：
{query}
"""

# 3. 生成阶段
response = llm.chat(prompt)
print(response)
```

### 常见进阶方向（待深入）

- [ ] **分块优化**：递归切分、语义分块、重叠窗口（Overlap）
- [ ] **检索优化**：混合检索（BM25 关键词检索 + 向量语义检索）
- [ ] **重排序（Rerank）**：用重排模型二次筛选 Top-K，大幅提高准确率
- [ ] **评估指标**：Faithfulness（真实性）、Answer Relevance（相关度）

---

### 小结

- RAG 本质是给大模型挂载一个“可实时更新的外部大脑/资料库”。
- 核心闭环是：**切块 -> 向量化 -> 检索匹配 -> 拼接上下文 -> 模型回答**。
- 适合做知识库、问答系统、代码查阅等注重准确度与私有数据的场景。
