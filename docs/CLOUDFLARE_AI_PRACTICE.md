# 🌐 Cloudflare AI 模块在本项目中的实战落地指南

> **背景说明**：截图展示的是 **Cloudflare 控制台** 中全套的 AI 产品矩阵。这套矩阵涵盖了大模型应用从**接入网关、边缘算力、向量检索、工具集成（MCP）到链路可观测性**的完整闭环。

## 🛠️ 各模块深度解析与项目落地用法

### 1. 模型（Models）与 Workers AI
- **产品定位**：Cloudflare 部署在海量边缘节点上的 Serverless 开源模型推理服务。**免自建 GPU 服务器，按调用量计费，开箱即用**。
- **支持的模型**：
  - **文本生成**：`@cf/meta/llama-3.1-8b-instruct`、`@cf/qwen/qwen1.5-14b-chat`
  - **Embedding 向量化**：`@cf/baai/bge-base-en-v1.5`、`@cf/baai/bge-large-en-v1.5`、`@cf/baai/bge-small-zh-v1.5`（强烈推荐作为 RAG 的向量模型）
  - **多模态/OCR**：`@cf/llava-hf/llava-1.5-7b-hf`
- **在我们项目中的落地用法**：
  1. **免费/极低成本切片向量化**：Python 端在做文档切块时，直接通过 API 调用 Cloudflare Workers AI 的 `bge-small-zh` 或 `bge-large` 生成向量，**无需本地买显卡，速度极快**。
  2. **边缘侧快速清洗与意图识别**：在用户提问时，先用 Llama 3 8B 做用户的意图分类或关键词提炼，成本几乎为零。

---

### 2. AI Gateway（核心必用 ⭐⭐⭐⭐⭐）
- **产品定位**：大模型 API 的**统一反向代理与治理网关**。位于我们的业务后端与底层大模型（OpenAI、Anthropic、Workers AI、DeepSeek）之间。
- **在我们项目中的落地用法**：
  1. **Token 费用监控与用量统计**：
     - AI Gateway 会**精确抓取并可视化记录**每一次请求的 `Prompt Tokens`、`Completion Tokens` 和预估费用，解决我们之前讨论的“Token 账单审计与对账”问题。
  2. **语义缓存（Semantic Cache / Response Caching）**：
     - 比如多个员工都问：*“今年国庆放假几天？”*
     - AI Gateway 会直接命中缓存返回之前的回答，**不仅耗时从 3 秒缩短到 50 毫秒，而且 0 Token 成本**！
  3. **限流（Rate Limiting）与防刷**：
     - 在网关层直接限制单个 IP / 单个用户的每分钟调用频次，防止 C 端用户恶意刷爆接口。
  4. **灾备高可用（Fallback / 自动降级）**：
     - 主模型配置 DeepSeek，如果 DeepSeek 官方接口网络抖动或超时，AI Gateway 自动切换调用 Qwen 或 Azure OpenAI，业务端完全无感知。

---

### 3. Vectorize（向量数据库）
- **产品定位**：Cloudflare 自研的全球分布式 Serverless 向量数据库，专为配合 Workers AI 与 RAG 设计。
- **特性与限制**：
  - **维度支持**：支持高达 1536 维（完美匹配大部分 Embedding 模型）；
  - **度量方式**：支持 `cosine`（余弦）、`dot-product`（点积）、`euclidean`（欧氏距离）；
  - **元数据过滤**：支持根据 Payload 字段做过滤。
- **在我们项目中的落地用法**：
  - 如果不想单独购买部署 Qdrant / Milvus 集群，可以**直接使用 Vectorize 作为我们的向量存储底座**；
  - 完美落地我们前面设计的：
    - 主键使用确定性 `UUIDv5`；
    - Metadata 里存入 `doc_code`、`chunk_id` 和 `acl_tags`，查询时在 Vectorize 内部做前置权限过滤。

---

### 4. MCP 门户（Model Context Protocol）
- **产品定位**：Anthropic 提出的全新开放协议（我们项目根目录的 `02_mcp` 就是针对它的），用于**让大模型像插拔 U 盘一样调用外部工具和数据源**。
- **在我们项目中的落地用法**：
  1. **连接企业内部接口**：通过 MCP 门户，把我们 NestJS 的接口（查审批状态、查员工部门、查请假单）包装成标准 MCP Server；
  2. **大模型工具调用（Tool Use）**：
     - 用户提问：*“帮我查一下文档 doc_123 现在的审批状态，并驳回它”*；
     - 大模型自动识别意图，通过 MCP 门户触发调用 NestJS 的 `POST /documents/:code/audit` 接口，完成操作。

---

### 5. AI 搜索（AI Search / Vector Search + Keyword）
- **产品定位**：融合了**向量语义检索**与**全文关键词检索（BM25）**的混合搜索方案（Hybrid Search）。
- **在我们项目中的落地用法**：
  - 单纯的向量搜索在处理**专有名词、产品型号、错误码（如 `ER_DUP_ENTRY`）**时容易失真；
  - 启用 AI 搜索做混合检索，并由系统内置的 Cross-Encoder 模型做重排序（Rerank），大幅提升知识库的准确率。

---

### 6. 智能体追踪（Agent Tracing / Observability）
- **产品定位**：针对复杂 Agent（智能体）、Multi-turn 问答与 LangChain/LlamaIndex 调用的**全链路拓扑追踪监控系统**。
- **在我们项目中的落地用法**：
  - 当一个大模型问答涉及：`用户提问 -> 检索向量库 -> 命中3个切片 -> 触发MCP工具查询天气 -> 最终生成回答` 时；
  - 智能体追踪会生成一条完整的 Trace 树状图，清楚看到：
    - 哪一步花了多长时间（是向量检索慢，还是大模型吐字慢？）
    - 哪一步报了异常；
    - 整个链条总共花掉了多少个 Token。排查线上“AI 答非所问或耗时过长”的神器！

## 📋 推荐落地路线图

| 阶段 | 模块选型 | 核心收益 |
| :--- | :--- | :--- |
| **第一阶段（立即接入）** | **AI Gateway** | 零代码侵入（只需把大模型 API 的 BaseURL 改为 Gateway 地址），立即获得 **Token 监控、缓存降成本、限流防刷**。 |
| **第二阶段（知识库接入）** | **Workers AI + Vectorize** | 无需购买自建昂贵的 GPU 和向量服务器，全套 Serverless 完成向量化与切片检索。 |
| **第三阶段（高级智能体）** | **MCP 门户 + 智能体追踪** | 接入动态工具库，并开启全链路追踪定位慢查询与 Bad Case。 |
