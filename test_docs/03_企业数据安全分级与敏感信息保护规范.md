# 企业数据安全分级与敏感信息保护规范指南

> **文件编号**：SEC-GOV-2026-012  
> **制定机构**：集团信息安全委员会 / 法务合规部 / 隐私保护办公室  
> **生效时间**：2026年3月1日  
> **适用范围**：全体正式员工、外包人员、实习生及第三方合作机构  
> **文档分类**：安全合规  
> **密级属性**：全员公开（PUBLIC）  

---

## 1. 概述与合规背景

### 1.1 编制依据
根据《中华人民共和国数据安全法》、《中华人民共和国个人信息保护法》（PIPL）、《网络安全法》以及 ISO/IEC 27001 信息安全管理体系标准，结合公司数字化转型业务实际，为规范集团内部及面向用户的数据全生命周期安全管理，特制定本规范。

### 1.2 数据安全治理总则
- **分类分级原则**：遵循“谁主管谁负责、谁使用谁负责、分类标识、层级防护”的原则；
- **最小必要原则**：应用系统及员工权限在收集、存储、使用、加工、传输数据时，必须严格限制在业务必需的最小颗粒度范围内；
- **纵深防御原则**：在网络隔离、身份认证、传输链路、应用接入与持久存储等全栈维度部署动态防御与可追溯审计。

## 2. 数据安全资产四级划分矩阵

公司所有数字化资产、业务数据库、接口载荷、文件凭证根据其遭到泄露、篡改、破坏后对国家安全、公共利益、公司商业声誉及用户个人合法权益的危害程度，划分为以下四个等级：

| 密级代码 | 密级名称 | 定义特征 | 典型数据样例 | 防护与访问管控要求 |
| :--- | :--- | :--- | :--- | :--- |
| **L1** | **公开数据 (PUBLIC)** | 可直接对社会公众发布、不具备排他性与商业秘密价值的信息 | 官网新闻公告、公开招股书、公开发布的产品白皮书、对外技术博客 | 无特殊加密要求，定期校验防篡改 |
| **L2** | **内部数据 (INTERNAL)** | 仅限公司内部员工日常工作流转查阅，对外泄露会带来轻微负面影响的信息 | 公司行政通告、通用工作流程文档、内部组织架构图、一般性业务规章 | 公司内网或通过企业 VPN 访问，禁止外发公网未授权平台 |
| **L3** | **敏感数据 (SENSITIVE)** | 涉及用户个人隐私（PII）或公司重要经营财务指标，泄露会引发重大声誉受损或合规处罚 | 用户姓名、手机号码、身份证件号、银行卡号、员工薪酬清单、月度未披露财报 | 强制字段级加密存储（AES-256），对外接口强制脱敏掩码，访问需严格审批授权 |
| **L4** | **绝密数据 (CONFIDENTIAL)** | 涉及公司核心技术知识产权、核心商业底牌及顶级运营安全凭据，泄露将危及公司生死存亡 | 数据库 Root 密码、服务器 SSL 私钥、生产环境 Cloudflare API Token、JWT 顶级根密钥、算法核心源码 | 物理/硬件安全模块（HSM）存储、动态密钥装载（Infisical）、严禁落盘明文，审计日志永久归档 |

## 3. 个人敏感信息（PII）脱敏与加密防护技术要求

### 3.1 显示脱敏（Masking）统一规则
所有业务管理中台、客服运营系统、对外打印单据及系统调试日志中，涉及个人隐私信息输出时，必须无条件遵循以下遮罩标准：

1. **中国大陆手机号码（11位）**：保留前 3 位和后 4 位，中间 4 位用星号替代。  
   *示例：`138****1234`*
2. **居民身份证件号码（18位）**：保留前 6 位和后 4 位，中间 8 位用星号替代。  
   *示例：`110101********1234`*
3. **银行卡号 / 对公账户**：仅保留前 4 位和后 4 位，其余统一采用连续星号遮蔽。  
   *示例：`622202******1234`*
4. **电子邮箱地址**：保留首字母及 `@` 后的域名，用户名中间字符以星号替代。  
   *示例：`m****g@company.com`*
5. **用户登录密码与短信验证码**：界面展示一律采用原点遮蔽（`••••••`），**系统日志与持久化数据库中严禁打印任何明文密码与明文验证码**。

### 3.2 存储与传输加密规范
- **传输层加密**：所有对外接口及内部微服务跨机房通信，必须强制启用 **TLS 1.3** 协议，禁止协商不安全的 DES/3DES、RC4 或 SHA-1 弱加密套件；
- **落盘静态加密（At-Rest Encryption）**：L3 级以上敏感数据在入库持久化时，必须采用 **AES-256-GCM** 或国密 **SM4** 算法进行对称加密；密码散列必须使用带独立盐值（Salt）的 **Argon2id** 或 **BCrypt**，哈希计算迭代次数不得低于 10 轮。

## 4. 研发与系统运维安全红线

为了杜绝工程层面的低级失误引发严重泄密，技术中心设立以下**研发合规高压线**：

1. **代码仓库与构建制品零硬编码（Zero Hardcoding）**：
   - 严禁在 GitHub、GitLab、Gitee 等代码库提交任何生产环境密码、数据库链接串、AK/SK 秘钥、API Token；
   - 必须通过集中式秘密管理平台（Infisical / Vault）在容器启动时动态环境变量挂载；
   - 本地开发测试环境所使用的配置，只允许保存在未纳入版本控制的 `.env.local` 文件中。
2. **生产环境跳板机与数据库操作门禁**：
   - 生产环境主机禁止通过密码远程 SSH 直连，必须通过统一堡垒机（JumpServer）并绑定硬件令牌（TOTP / 2FA）；
   - 研发人员一律不得申请生产数据库的高危 DDL/DML 直接写权限；生产临时查询必须提交 SQL 工单，经技术总监审批后，在脱敏沙箱中执行且最大返回行数不得超过 1000 行。
3. **测试数据使用规范**：
   - 严禁直接使用未经脱敏的生产真实数据库快照作为本地开发或集成测试环境数据源；
   - 测试环境一律采用经过算法合成的 Mock 虚拟数据或清洗脱敏后的合规数据包。

## 5. 安全漏洞与应急响应时效考核（SLA）

根据漏洞危害范围与可能造成的潜在经济合规损失，安全团队将应急响应与修复时效划分为三级严密标准：

| 风险等级 | 判定情形样例 | 首次响应与定级时限 | 临时止血与缓解时限 | 彻底代码修复与发布时限 |
| :--- | :--- | :--- | :--- | :--- |
| **P0 (特别重大)** | 生产数据库遭未授权外泄、核心业务遭遇 RCE 远程命令执行、支付鉴权逻辑绕过 | **≤ 15 分钟** | **≤ 2 小时** (如下线接口/切熔断) | **≤ 24 小时** |
| **P1 (严重风险)** | 越权访问批量敏感用户数据、生产跳板机遭遇暴力破解、核心业务服务大面积挂起 | **≤ 30 分钟** | **≤ 6 小时** | **≤ 48 小时** |
| **P2 (中度风险)** | 内部管理系统 XSS 反射型漏洞、敏感信息报错回显未脱敏、CSRF 防护缺失 | **≤ 2 小时** | **≤ 24 小时** | **≤ 5 个工作日** |

## 6. 员工保密责任与离职交接

1. **在职保密纪律**：员工不得将公司内网代码、知识库文档、客户往来邮件擅自备份至个人网盘（百度网盘、阿里云盘等）、外部 AI 大模型未授权对话框或私人 GitHub 个人公开仓库；
2. **离职权限回收机制**：
   - 员工提出离职审批通过后，HR 与 IT 系统联动触发“权限预回收机制”；
   - 离职生效当日 **18:00 前**，自动化脚本全量注销其企业微信、飞书、Git 账号、VPN、OA 及所有云平台访问密钥，完成物理资产（办公电脑、移动硬盘）的安全格式化交接并留档存查。
