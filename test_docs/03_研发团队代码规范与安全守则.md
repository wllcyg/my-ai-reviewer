# 研发团队代码规范与安全守则 (v2.0)

> 本规范适用于前后端研发人员，所有代码合并前必须经过 Sonar 静态扫描与同行代码评审。

## 一、通用安全规范

- **严禁凭据硬编码**：任何 AccessKey、Secret、数据库密码禁止直接写入代码仓库；
- **输入校验**：所有面向外部暴露的 API，必须使用 `class-validator` 或 `pydantic` 进行类型守卫。

## 二、Git 提交与分支策略

| 分支名称 | 定位与准入规则 | 部署环境 |
|---|---|---|
| `main` | 生产稳定分支，仅允许 PR 合并 | Production |
| `release` | 预发环境分支，准入冒烟测试 | Staging |
| `develop` | 日常联调集成主干 | Development |

## 三、异常处理与日志标准

```typescript
try {
  await this.processTransaction();
} catch (error) {
  this.logger.error(`[交易处理失败]: ${error.message}`, error.stack);
  throw new BusinessException('系统繁忙，请稍后再试');
}
```
