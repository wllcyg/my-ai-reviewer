## 1. 执行摘要与产品愿景

在现代大型研发型企业中，知识孤岛、代码质量审查标准参差不齐、技术规范更新与落地脱节是制约组织工程效能的关键痛点。

**My-AI-Reviewer（企业级 AI 智能评审与知识协同平台）** 应运而生。本平台以自研的“**双路混合检索增强生成（RAG Hybrid Search）**”与“**多智能体异步审查流（Multi-Agent Review Pipeline）**”为核心技术底座，打通“代码变更审查（Git PR/MR Review）”与“企业全生命周期制度文档知识库”，为企业研发团队、合规团队及业务部门提供高精准、高安全、毫秒级响应的企业级知识中台。

## 3. 双路混合检索与 RRF 融合重排算法

### 3.1 为什么单一向量检索（Dense Vector）无法满足企业场景？
在真实的制度和代码检索场景中，单纯依赖稠密向量检索存在两类致命缺陷：
1. **专有名词与精确编号丢失**：如搜索特定规章编号（`FIN-POL-2026-003`）、特定错误码（`ERR_SOCKET_TIMEOUT`）、人名或特定数值，语义向量往往因被平均嵌入而发生漂移；
2. **长尾冷门词与生僻缩写失准**：对未经海量泛化训练的领域专有名词，余弦相似度区分度极低。

为此，平台创新构建了“**语义向量（Cloudflare Vectorize） + 稀疏倒排关键词（Bonsai OpenSearch BM25）**”双轮驱动模型。

### 3.2 倒数排名融合算法（Reciprocal Rank Fusion, RRF）
平台使用 RRF 算法将来自向量检索引擎与全文倒排检索结果进行无监督评分对齐，避免因两端原始 Score 量纲不同造成的偏置失真。其融合数学公式为：

$$RRF(d) = \sum_{m \in \{Vector, BM25\}} \frac{w_m}{k + \text{rank}_m(d)}$$

- $d$：候选文档分块（Chunk）；
- $m$：召回通路（向量路或全文检索路）；
- $k$：平滑调节常数（系统默认设定为 $k = 60$），防止排名第一的候选者权重过大；
- $w_m$：通路权重系数（默认 $w_{vector} = 1.0, w_{bm25} = 0.8$）；
- $\text{rank}_m(d)$：文档分块在通路 $m$ 中的排序名次（从 1 开始）。

经过 RRF 融合计算后，既能命中语义相关的宏观概念段落，又能精准捕获含有特定条款编号或参数要求的确切文字。

## 4. 全生命周期文档流转与安全多租户权限设计

### 4.1 文档四态流转生命周期
知识库中所有上传文档严格遵循闭环状态机管理：

```
[草稿 DRAFT] ───(提交审核)───► [待审核 UNDER_REVIEW] 
                                    │
                                    ├───(审核驳回)───► [草稿 DRAFT] (可编辑重提)
                                    │
                                    └───(审核通过)───► [已发布 PUBLISHED]
                                                            │ (触发三路异步索引)
                                                            ▼
                                                       [已归档 ARCHIVED]
                                                       (实时清理向量与全文索引)
```

1. **DRAFT（草稿箱）**：允许作者反复编辑、替换附件及在线调整元数据，此阶段不对知识库其他用户提供检索服务；
2. **UNDER_REVIEW（待审核）**：触发 AI 自动化审查流水线，由合规大模型自动给出安全走查评分与整改建议；
3. **PUBLISHED（已发布）**：审批通过后自动触发 RabbitMQ 双路投递，在 Cloudflare Vectorize 与 Bonsai OpenSearch 中生成切片索引，向授权员工开放 RAG 问答；
4. **ARCHIVED（已下线归档）/ 删除**：无论何时下线或硬删除文档，系统立即发起 `Promise.allSettled` 并发事务，**物理擦除其在云端 Vectorize 与 Bonsai 中的全部向量切片与倒排分词文档**，确保被下线文档绝对不再出现在 AI 问答引用中。

### 4.2 三层权限范围控制（Scope ACL）
文档数据支持细粒度可见范围隔离：
- **PUBLIC（全员公开）**：任何登录系统的员工均可在知识库查阅并在 AI 聊天框中检索此知识；
- **DEPT（部门级定向授权）**：基于组织架构多选树（TreeSelect），仅被勾选授权的一级或二级部门成员具备查阅与检索权限；在底层向量及 OpenSearch 查询时，系统自动在检索 Filter 中注入 `scope IN ('PUBLIC') OR visibleDeptIds INTERSECT userDeptIds`；
- **PRIVATE（私密保密）**：仅文档创建者本人及系统超级管理员拥有查看权限。

## 5. 多格式文档切片与结构化解析引擎

### 5.1 支持的文件格式
平台依托底层统一解析引擎，支持包括但不限于以下 6 种主流办公与技术文件格式：
- **Markdown (`.md`)**：依据一级、二级、三级标题树层级进行语义感知切片（Semantic Chunking），自动生成带有标题面包屑导航的元数据上下文；
- **纯文本 (`.txt`)**：内置智能编码探测器（自动识别 UTF-8、GBK、GB2312 等编码），采用滑动重叠窗口（Chunk Size: 600, Overlap: 100）切分；
- **Word (`.docx`, `.doc`)**：提取段落结构、正文粗体、表格结构并转化为结构化 Markdown 流；
- **Excel / CSV (`.xlsx`, `.csv`)**：表格二维数据按行解析转置为自然语言描述句子，保留表头语义；
- **PPT (`.pptx`)**：按幻灯片页码逐页提取标题与要点正文；
- **PDF (`.pdf`)**：基于 PyPDF / PDFPlumber 进行版面分析与流式文本提取。
